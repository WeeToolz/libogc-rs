# TODO: Safe wrappers and unsafe-code review

> Do not change an `unsafe fn` to a safe function merely to remove the
> `unsafe` keyword. An API may become safe only when its implementation
> enforces all pointer, lifetime, aliasing, threading, callback, DMA, and
> Wii-specific requirements.

## Completion criteria

- [ ] Provide safe slice, reference, handle, or owned-buffer wrappers where practical.
- [ ] Keep ABI-compatible raw-pointer and `-sys` entry points unsafe.
- [ ] Document every public unsafe function with a precise `# Safety` contract.
- [ ] Encode asynchronous buffer and callback lifetimes in owned request or playback handles.
- [ ] Prevent callbacks from observing freed or moved callback context.
- [ ] Verify DMA alignment, cache coherency, and buffer lifetime requirements on Wii.
- [ ] Review every `unsafe impl Sync` and `unsafe impl Send` for an enforced invariant.
- [ ] Review interrupt-context code for locks that can deadlock on the single-core Wii.
- [ ] Avoid function-pointer `transmute`; use signature-correct trampolines or storage.
- [ ] Run the appropriate `cargo xtask check-group ...` checks after each conversion.
- [ ] Run hardware probes before declaring Wii runtime behavior verified.
